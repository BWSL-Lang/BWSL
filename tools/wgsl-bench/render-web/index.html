Workloads, correctness and limitations

Skinned GGX: four instanced 64×64-cell meshes, four bone influences from a 64-bone palette, 32,768 triangles and four point lights per fragment. Procedural MRT: a fullscreen analytic material, derivative-based antialiasing, color and normal/roughness attachments. Particles: 16,384 billboards in four overlapping layers with alpha blending.

All input buffers are checked exactly before and after timing. Every attachment pixel is compared between sources, allowing three RGBA8 levels; integer targets are exact. Procedural MRT and particles also have independent full CPU image references. Skinned GGX has independent software-rasterized interior color probes plus full-image cross-comparison. Reports retain maximum errors, attachment hashes and 256-pixel previews.

A separate GPU regression checks sparse varyings, integer flat interpolation, linear interpolation with varying clip W, fragment coordinates and depth, sparse integer MRT, output snapshots and nonzero vertex/instance offsets. It runs before timing.

The textured material uses matrix and nested uniform reads, a padded scalar array, explicit-LOD sampling, a runtime loop, and conditional discard. A separate constant nested-loop continue regression runs before timing.

Compilation records first-observed and ten repeated-source pairs after two warmups. GPU order alternates AB/BA with a seeded starting order. Neither repeated samples nor confidence intervals account for all thermal/systematic effects. One GPU and these four workloads do not establish general parity.

The native WGSL backend supports scalar/vector stages, structured control flow, primitive storage buffers, std140 uniforms and sampled textures. Local arrays, general aggregate values, storage textures, texture offset overloads, workgroup memory and atomics remain unsupported. WGSL uniformity rules still apply to derivatives and implicit-LOD sampling.
